# Image Brief: Responsible AI Sensification Architecture

This prompt is a presentation asset, not implementation documentation. Keep the
rendered labels aligned with the active architecture below.

## Paste-ready prompt

Create a polished 16:9 research-system diagram titled **Responsible AI
Sensification**, subtitled **From Gemma 3 observations to browser sound and
external visual/audio receivers**. Use a dark charcoal background, crisp white
type, restrained cyan/green/amber/magenta accents, and legible signal arrows.

Show four left-to-right zones:

1. **Ubuntu GPU PC — Emitter runtime**
   - user prompt;
   - Gemma 3 language model;
   - movable selected-block dense residual observation;
   - Gemma Scope sparse autoencoder fixed at its trained layer;
   - sparse active feature list with Neuronpedia descriptions;
   - optional local semantic-tonality interpretation;
   - browser audio/visual mapping controls.

2. **FastAPI Emitter boundary**
   - `/ws/stream` to the controlling browser;
   - passive rich JSON at `/ws/activations` with run/model/site provenance and
     the complete sparse active list;
   - optional `/rai/v1` OSC carrying bounded post-tonality notes and controls;
   - make clear that passive observation and OSC routing are independent.

3. **Receivers**
   - browser Web Audio and local visual workbench;
   - TouchDesigner WebSocket DAT feeding feature/state tables and a future
     project-specific visual network;
   - the existing Windows Max for Live/ossia receiver consuming `/rai/v1`;
   - ossia score as a candidate timeline/automation receiver, with OSCQuery
     discovery clearly marked future.

4. **Development and validation**
   - deterministic NDJSON activation replay for passive observers without model
     loading;
   - separate `/rai/v1` model-free OSC fixture;
   - browser tests, server tests, loopback checks, then real host validation.

Use solid arrows only for implemented paths and dashed arrows for future
TouchDesigner artwork, OSCQuery discovery, or bidirectional cross-host controls.
Include a legend distinguishing **raw observation**, **interpretation**,
**artistic transformation**, and **Connector routing**. Do not depict a second
unversioned OSC activation bus, default broadcast ports, cloud inference, or a
replacement Max receiver.
